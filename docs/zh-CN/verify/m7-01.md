# M7：首次安装与登录认证

## 范围

本轮实现：

- `users` 表与默认管理员；
- 首次启动安装向导；
- 管理员密码登录、签名 Session、CSRF；
- `/mcp` 独立 Bearer Token；
- 多 MCP Token 管理（创建/物理删除/分页）；
- 审计 actor 改为真实管理员；
- Session 有效期进入系统配置；
- 非 loopback 远程监听需要显式开关 + HTTPS 公网地址。

未完成/边界：

- 多用户、角色管理、按 target 授权；
- OAuth/OIDC、MFA、密码找回；
- 多用户、角色管理、按 target 授权（当前单管理员）；
- 密码找回页面（已提供本地 CLI `dr-panda-mcp-admin reset-password`）；
- 反向代理实机 TLS 验收；
- 服务端 Session 表（当前为无状态签名 Cookie）；
- `data/install.json` / `install.key` 丢失后的恢复流程。

## 安装向导

启动顺序：

```text
load config
→ load data/install.json
→ 无安装状态：SetupApp
→ /setup/admin：设置 admin 密码（最少 8 位，scrypt 哈希暂存内存）
→ /setup/database：选择 SQLite/MySQL/PostgreSQL
→ /setup/database 测试连接
→ 完成：迁移配置库 → 创建 admin → 生成 MCP Token → 写 install.json
→ 正常 Web/MCP
```

- 安装状态：`data/install.json`，数据库 URL 用 `data/install.key` AES-GCM 加密；权限 0600。
- 密码、MCP Token 不写入 install 文件。
- 安装状态不存在时，普通 Web 只暴露安装/healthz/static；`/mcp` 返回 503。
- Setup 页面只应在 loopback 启动；非 loopback 且未安装时启动失败。
- 完成页显示一次 MCP Token；关闭后不再显示。
- 已有旧库但无 users 时，默认 SQLite 路径指向旧库，完成后保留 targets/settings/audit。

## 认证

### users

`0004_users` 新增：

- `id`
- `username`（唯一）
- `password_hash`
- `role`（默认 admin）
- `is_enabled`
- `auth_version`
- `mcp_token_hash`（唯一，可空）
- `last_login_at`
- `created_at`、`updated_at`

安装完成时创建唯一 `admin`，不 seed 默认密码。

### Web

- `POST /login`：用户名/密码；scrypt 校验；失败 401。
- Session：HMAC-SHA256 签名 Cookie `drpanda_session`，HttpOnly、SameSite=Lax、HTTPS 下 Secure。
- 有效期：系统配置 `session_ttl_minutes`，默认 720（12 小时），范围 5–10080；中间件按当前配置校验 `iat`。
- `POST /logout`：清 Cookie。
- 未认证 Web GET/POST 303 → `/login?next=...`；`/healthz`、`/static`、`/login` 公开。
- 所有 Web POST 使用双提交 Cookie CSRF（`drpanda_csrf` + `_csrf`），失败 403。
- 审计 actor 和 `settings.updated_by` 使用登录用户名。

### MCP

- `Authorization: Bearer <token>`。
- 服务端 `users.mcp_token_hash = SHA-256(token)`，固定时间比较由哈希查询完成。
- 缺失/错误 → 401 + `WWW-Authenticate: Bearer realm="dr-panda-mcp"`。
- 不接受 Cookie、query token 或其他 header。
- 认证通过后工具审计 actor = `admin`。

### MCP Token 管理

- 安装完成时展示一次原始 Token；服务端只存哈希，不保存可逆明文。
- 迁移 `0006_mcp_tokens` 新增 `mcp_tokens`：
  - `id`
  - `user_id`
  - `name`（可空）
  - `token_hash`（唯一）
  - `token_prefix`
  - `created_at`
  - `last_used_at`
- 旧 `users.mcp_token_*` 字段和旧 Token 按用户要求直接删除；旧 Token 立即失效，不做迁移、不保留名称。
- 新安装创建第一条 Token，`name=NULL`。
- `/me` 显示 MCP 地址和 Token 列表，列表 20 条/页，不设数量上限。
- 点击“生成新 Token”使用原生 `<dialog>` + `app.js` 弹窗，不跳转独立页面；无 JS 时回退到 `/me/tokens/new` 表单。
- 列表只显示名称、前缀、创建时间、最近使用时间，不显示完整 Token。
- 创建 Token 不要求当前密码；名称可选。
- 删除 Token 不要求当前密码，使用原生 `<dialog>` + `app.js` 二次确认弹窗；无 JS 时回退独立确认页；物理删除，删除后立即失效，不可恢复。
- Token 名称在同一管理员下做应用层重复检查；空名称允许。
- 本地管理员密码重置：`uv run dr-panda-mcp-admin reset-password`。
- 不做轮换，不做撤销。
- 创建结果页 `Cache-Control: no-store`，`Referrer-Policy: same-origin`，完整 Token 只显示一次。
- Token 结果弹窗提供复制按钮：静态 `copy-token.js` 渐进增强；无 JS 时按钮隐藏，显示全选 + ⌘C/Ctrl+C 提示；复制失败不谎报成功。
- 修复：`/me` 原先设置 `Referrer-Policy: no-referrer`，Chrome 在表单 POST 时发送 `Origin: null`，被 FastMCP Host/Origin 拦截为 403；改为 `same-origin` 后同源表单正常。
- `last_used_at` 在认证成功时节流更新（约每分钟最多一次）。

### 修改密码

- `/me` 提供当前密码、新密码、确认新密码。
- 最少 8 位，不能与当前密码相同。
- 成功后 `auth_version += 1`，清空当前 Session，旧密码失效，需重新登录。
- 写审计 `user.password_change`。
- 修改密码不自动删除 MCP Token；需要撤销客户端时删除对应 Token 并创建新的。

## 配置

新增配置：

| key | 默认 | 范围 | 说明 |
|---|---:|---:|---|
| `session_ttl_minutes` | 720 | 5–10080 | Web Session 最长有效期 |

新增环境变量：

- `DR_PANDA_ALLOW_REMOTE=1`：允许非 loopback 监听；
- `DR_PANDA_PUBLIC_URL=https://...`：远程访问的公开 HTTPS 地址，用于 Host/Origin 与 Secure Cookie。

前置仍是：安装必须在 loopback 完成。

## 真实 MySQL/PostgreSQL 安装联调

环境：

- MySQL 8.0.36 Docker，`127.0.0.1:3307`
- PostgreSQL 16 Docker，`127.0.0.1:5433`
- Python 依赖：`asyncmy`、`asyncpg`

链路：

1. 安装向导设置 admin 密码；
2. 选择 MySQL/PostgreSQL，填写连接信息；
3. 测试连接成功；
4. 完成安装：执行到 `0006_mcp_tokens`，创建 users/admin，settings 9 行；
5. 从 `data/install.json` 重新加载配置库 URL；
6. 重新创建正常应用，登录成功；
7. `/mcp` Bearer initialize 成功，未认证 401。

发现的真实兼容性问题并已修复：

- MySQL 中 `key` 是保留字：迁移脚本和启动备份读取里的 `SELECT key FROM settings` 改为 SQLAlchemy 列引用。
- MySQL 的 `TEXT` 列不能带默认值：`settings.description` 先以可空列加入、回填后再收紧为 NOT NULL。

验证结果：

```text
MySQL:      tables 6, users=admin/admin, settings=9, alembic=0006_mcp_tokens
PostgreSQL: tables 6, users=admin/admin, settings=9, alembic=0006_mcp_tokens
MySQL/Postgres: setup -> restart -> login -> /mcp initialize 全部通过；mcp_tokens 表创建、旧 token 列删除
```
