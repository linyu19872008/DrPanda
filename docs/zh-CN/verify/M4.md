## 手动验证（真实 HTTP MCP）

启动服务（8133），登记一个 CLS 目标后通过 `fastmcp.Client("http://127.0.0.1:8133/mcp")`：

```
tools: ['cls_context', 'cls_search', 'gitlab_blame', 'gitlab_get_file', 'gitlab_search_code', 'systems_status']
prompts: ['investigate_error']
cls_search error: UPSTREAM_UNAVAILABLE: cls 客户端未安装：uv sync --extra cls
prompt head: 你是线上故障排查助手。全部工具只读，不能修改任何线上状态。
systems_status: {'targets': 1, 'enabled': 1}
audit: tool.call|logs-cls|cls_search target=logs-cls params={"query": "level:ERROR", ...} returned=0 elapsed_ms=2 error=UPSTREAM_UNAVAILABLE
```

说明：未安装 `tencentcloud-sdk-python-cls` 时工具返回明确的可操作错误，且失败也写入审计；这正是 V4.8 缺凭证时的预期行为。

## 说明与未验证项

- **CLS TopicId**：登记的 topic 支持 `日志集/topic` 写法，调用 API 时取最后一段作为 `TopicId`；`cls_search` 在目标仅授权一个主题时可省略 `topic`。
- **GitLab 跨项目搜索**：`project` 省略时只在授权项目内逐个搜索，不发起全局搜索。
- **文件截断**：`gitlab_get_file` 按目标 `max_bytes` 截断内容并标记 `truncated`；这是显式截断，不再二次裁掉整行。
- **未验证**：真实 CLS 检索与上下文、真实 GitLab 仓库的搜索/读文件/blame；需要只读凭证或对应 extras 后手测，不能当作通过。
