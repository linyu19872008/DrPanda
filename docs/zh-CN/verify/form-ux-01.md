# 新建目标表单交互优化

## 背景

`/targets/new?type=mysql` 原先一次性展示 16 个字段，TLS、mTLS、PROCESSLIST、运行限制全部展开；右侧有 4 张帮助卡。

审计发现：

- 文本、布尔、密钥字段错误显示 `Default ; range —`；
- PEM 与 checkbox/password 混排，PEM 只有半列宽；
- Password 被放到“密钥”区，与连接信息割裂；
- CA/mTLS 字段不随 SSL 状态变化；
- 保存前不能测试连接；
- 页面 1440 高约 2067px，390 高约 3361px。

## 改造

### 字段结构

```text
基本信息
连接（Host/Port/User/Password/默认库）
授权范围
高级设置（折叠）
  TLS / 证书
  运行限制
```

- Password 移入连接区；
- TLS、CA、客户端证书、PROCESSLIST、运行限制默认折叠；
- 必填字段增加 `required` / `aria-required`；
- 文本和布尔字段不再显示无意义的默认值/范围；
- 新建密钥显示“必填”，编辑显示“已设置/可选”；
- PEM 字段独占整行，使用等宽字体；
- 右侧帮助压缩为一张卡片，命名规则和密钥说明用 `<details>` 折叠。

### 测试连接

表单底部新增“测试连接”：

- 使用当前表单值构造临时 target；
- 不写库、不创建目标；
- 探测前仍走只读闸门；
- 成功后显示“连接测试通过”，失败显示脱敏错误；
- 无 JS 时仍是普通 POST 表单。

### 高级设置与 TLS

- 高级设置默认折叠，出现高级字段错误时自动展开；
- 勾选 SSL/TLS 后才显示 CA、客户端证书、私钥；
- Kafka 只在 `SSL` / `SASL_SSL` 下显示 TLS 材料；
- 无 JS 时全部显示，服务端继续做依赖校验。

### 交互细节

- 页面标题旁增加“切换类型”；
- 提交加载态覆盖测试连接/保存；
- 表单错误重新渲染后，自动聚焦第一个错误字段。

## 结果

| 指标 | 改造前 | 改造后 |
|---|---:|---:|
| 1440 页面高度 | 约 2067px | 约 1237px |
| 390 页面高度 | 约 3361px | 约 1870px |
| 首屏字段 | 16 个 | 10 个左右 |
| 保存前测试连接 | 无 | 有 |
| 右侧帮助卡 | 4 张 | 1 张可折叠 |

真实 Chrome 验证：

- 1440/390 无横向滚动；
- 高级设置默认关闭，点击可展开；
- 勾选 SSL 后 CA/mTLS 字段出现；
- 表单底部操作条不再 sticky 覆盖字段；
- 测试连接和创建目标均可见。
