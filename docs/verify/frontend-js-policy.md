# 前端 JavaScript 约束（v2）

## 背景与两次调整

项目早期采用“严格零客户端 JavaScript”。第一次调整（v0.32）改为“服务端优先 + 局部渐进增强”，允许自托管、无依赖的 JS 处理剪贴板、原生 dialog 等纯 CSS 做不到的高价值交互。

v0.36 做第二次调整：**取消「脚本不发额外网络请求」这条禁令**，允许**同源 fetch**。原因是这条约束把“控制前端复杂度/供应链风险”错误地等价成了“禁止同源请求”：

- 风险来自框架、构建链、第三方 CDN、远程字体，不来自“自己的页面调用自己的接口”；
- 禁止同源请求导致长耗时/可失败动作只能整页刷新：滚动位置、筛选分页、未保存输入、密钥输入全部丢失；
- 为了补这些坑，反而要在服务端引入临时状态（票据、会话暂存、状态回填），复杂度和泄密面都变大；
- “测试连接”这类外部操作天然适合异步 + 局部反馈，硬塞进整页 POST 会把它和“保存”耦合成同一个表单动作。

以下三条**没有变，也不允许变**：

1. **服务端是唯一事实来源**：认证、权限、CSRF、Host/Origin、字段校验、只读闸门、保存门槛都由服务端执行；前端状态只用于体验。
2. **核心流程无 JS 或 JS 加载失败时仍可用**：每个异步动作都有等价的普通表单路径。
3. **不出现假按钮**：失败要如实提示，不能显示“能点但没反应”的功能。

## 规则

### 必须保持

- Jinja2 服务端渲染为基线；页面以 SSR 内容为主，脚本只改动当前页已渲染的 DOM。
- 所有核心流程（登录、目标增删改/启停/测试、系统配置、Token 创建/删除、安装向导）在无 JS 时用普通 HTTP 表单完成。
- 不引入 React/Vue/Next 等前端框架，不引入 npm/Node 构建链，不引入外部 CDN、字体、第三方脚本。
- 服务端对 JSON 请求与普通表单请求执行同一套校验；前端不得代替或跳过任何服务端校验。
- 不在 localStorage / sessionStorage / URL / 日志里保存 Token、密钥或连接串。
- 请求只允许同源（相对 URL），并携带 CSRF（表单里的 `_csrf` 随请求体提交）。
- JSON 响应 `Cache-Control: no-store`；错误信封统一为 `{ok, code, message, errors, phase, redirect}`。
- 加载态：按钮禁用 + 文案切换 + `aria-busy`；结果用 `role=status` / `role=alert` 表达。
- 单飞与超时：同一表单/行同时只允许一个请求；请求用 `AbortController` 超时并给出可重试提示。
- 安全响应头：`Content-Security-Policy`（`script-src 'self'`、`connect-src 'self'`、`form-action 'self'`、`frame-ancestors 'none'` 等）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: same-origin`。模板不写内联脚本/内联样式。

### 允许

- 同源 `fetch` + `FormData`/`URLSearchParams` + `AbortController`。
- 局部 DOM 更新：行内状态、结果提示、错误回填、开关状态、统计数字。
- 本次页面交互状态：脏标记、加载态、已测快照、展开态、弹窗；仅用于体验。
- 原生 `<dialog>`、剪贴板复制等既有渐进增强。
- 服务端预渲染的文案/片段由服务端提供，脚本只负责挂载。

### 禁止

- 用脚本改写认证、CSRF、Host/Origin、权限、只读闸门或保存门槛。
- 把“页面看起来没报错”当作成功；网络失败/解析失败必须提示。
- 把密钥、Token 写入 JS 可访问的持久化存储或日志。
- 为了动画/视觉引入大型运行时；为了异步而把页面改成 SPA（路由、虚拟 DOM、全局状态库）。
- 依赖第三方 CDN 或远程字体。

## 一个必须记住的坑：别在 submit 里禁用 submitter

表单数据是在 `submit` 事件**之后**才构造的；被禁用的提交按钮不再算提交按钮，它的 `name/value` 不会进入请求体。历史实现为了防重复提交，在 `submit` 里禁用所有 `button[type=submit]`（包括刚被点击的那个），结果：

- 目标表单点「测试连接」（`name=action value=test`）实际执行了「保存」；
- 安装向导点「完成安装」（`action=finish`）实际又执行了一次「测试连接」，安装永远完不成。

现行做法：提交时先把 submitter 的 `name/value` 镜像成隐藏域，再禁用按钮（见 `app.js` 的 `mirrorSubmitter`）。新增带 `name` 的提交按钮时不要绕过这段逻辑。

## 无 JS 回退

- 目标表单：保存按钮可直接提交，服务端**先探测再保存**，探测失败不写库；「测试连接」走普通 POST 重渲染并展示结果。
- 列表测试/启停/删除、系统配置保存、修改密码、登录、安装向导：普通表单 POST + 303 / 重渲染。
- Token 创建/删除：独立结果页与确认页；复制按钮无 JS 时隐藏并提示手动复制。
- 所有表单仍由服务端校验、CSRF 与权限边界保护。

## 验证

- 服务端 JSON 契约、探测接口、保存门槛、无 JS 路径均有 pytest 覆盖（`tests/test_web_async.py`、`tests/test_web.py`）。
- 关键浏览器路径用 CDP 真机验收：测试连接 → 保存解禁 → 改字段重新置灰 → 保存跳转；列表行内测试/启停不刷新；设置保存不跳页；安装向导测试 → 完成安装；禁用 JS 后保存按钮直接可用。
- 验证记录见 `docs/verify/async-ux-01.md`。
